# 黄金替罪羊求解器

从首页打开「黄金替罪羊求解器」，也可以直接访问 `/golden-scapegoat`。工具支持绘图、最短路径搜索和逐步回放。使用「导出 JSON」下载地图，用「导入 JSON」继续编辑。

## 绘图与回放

1. 选择元素，点击格子放置。使用键盘时，可在地图内用方向键选格，再按 Enter 放置。擦除只作用于选中的元素层及当前关联组。梯子通过选择同列的两个端点绘制，擦除其经过的格子会移除经过该格的梯段。
2. 为羊可站立的格子放置固定平台或活动平台。S、G、梯子、机关和传送门另占图层。放置平台或传送门机关前，先新建或选择对应组。地图用 A1、A2 等标识平台组，用 P1、P2 等标识传送门配对。
3. 设置 K、起点 S 和终点 G，补齐每对传送门的两个端点。活动平台组可设置未踩机关和踩住机关时是否提供支撑。同组机关采用 OR，任一机关被占用就采用踩住时的设置。
4. 选择「开始求解」。Worker 搜索默认最多访问 100,000 个状态、运行 5 秒，限额可分别调整至 250,000 个状态和 30 秒。取消、编辑地图、换图和离开页面都会终止进行中的任务。
5. 找到解后，用首尾和前后按钮检查各帧。帧 0 是初始环境结算后的状态。后续每帧对应一次有效操作及其引发的环境事件。面板同时显示羊的位置、回放阶段、各组状态和本步事件，并支持复制方向箭头或 WASD。

「视窗与缩放」可以移动起始坐标、调整显示行列和格子大小。坐标为整数，X 向右、Y 向下，允许负值。地图可录入 ±1,000,000 范围内的坐标。编辑视窗的边缘没有碰撞或阻挡效果。回放会跟随金羊，并在空间足够时同时显示黑羊。

## JSON 格式

版本 1 的根对象包含 `version`、`k`、`start`、`goal`、`floors`、`platformGroups`、`ladders` 和 `portalPairs`。坐标写为 `{"x": 0, "y": 0}`。

| 字段             | 内容                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| `version` / `k`  | 固定为 1 的文件版本 / 正安全整数 K                                                                           |
| `start` / `goal` | 坐标，草稿可以为 `null`                                                                                      |
| `floors`         | 固定平台坐标数组                                                                                             |
| `platformGroups` | 每组含 `id`、布尔值 `defaultEnabled` / `activatedEnabled`、平台坐标数组 `cells` 和机关坐标数组 `controllers` |
| `ladders`        | 每段含同列的 `top` / `bottom` 坐标，`top.y < bottom.y`                                                       |
| `portalPairs`    | 每对含 `id`、端点坐标数组 `ends` 和机关坐标数组 `controllers`                                                |

组 ID 在同类组中必须唯一。空白地图、缺少 S 或 G 的地图以及尚未放齐传送门端点的地图可以保存为草稿。文件大小上限为 1 MiB。导入结构或布局非法时，编辑器保留当前地图，并报告字段路径或格子坐标。活动平台格与机关重叠会被拒绝。传送门端点与机关叠放属于游戏规则待验证的组合，当前工具也会拒绝该布局。

## 规则与当前假设

金羊左右各移动一格，沿梯子直接移动到对应端点。无效的金羊输入不推进步数或回放。第 K 次有效操作结算后在 S 生成黑羊，并立即结算它带来的环境变化。黑羊从第 K+1 步起尝试回放记录，依次消费指令。回放结束后保持位置，仍参与环境结算。

每步先从旧状态计算并同时提交两羊的主动位移。根据新位置检查终点与碰撞，读取机关并刷新支撑，再处理传送和同步坠落。一次操作引起的连锁变化会在下一步前全部结算。双端同步传送允许交换位置，门随后关闭。传送门在机关格从无人占用变为有人占用时开启，并保留开启状态至传送。当一只羊持续按住开关导致另一只羊往返传送时，往返的羊会消失。

以下边缘情形采用了 MVP 假设，表中的摆法仅用于验证时序，均为合成场景。

| 验证摆法                                                         | MVP 行为                                           | 实机待核对的行为                                 |
| ---------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------ |
| 金羊走入空列，列中间有无支撑的传送门机关，下一格有落脚平台       | 经过机关时不激活，只有站在有固定平台的机关格才触发 | 经过机关也可能开门                               |
| 开启的门位于即将消失的活动平台上，金羊和令平台消失的黑羊同时到位 | 优先从已经开启的端点传送，再在落点判断重力         | 可能先坠离门格                                   |
| 黑羊站在 G，金羊横移进入同一格                                   | 同一位置快照先判定金羊到达 G                       | 游戏可能先判碰撞                                 |
| 两个有固定平台的梯子端点之间放置 G，或关闭某个端点的活动平台     | 梯子主动位移只检查端点，端点失去支撑后会下落       | 可能检查梯子途中位置，或者允许在无支撑的端点挂梯 |
| S 未配置平台，G 位于 S 正下方                                    | 初始化即结算坠落，经过 G 得到零步解                | 实机编辑规则可能要求 S 或 G 自带支撑             |

每次同步下落跳过无事件的空段，在下一处地图元素、潜在碰撞位置或最下方已录入格子的下一行重新结算。坠出后金羊失败，黑羊消失；黑羊消失后仍可继续求解。

搜索和回放共用同一状态转移。BFS 以有效操作计成本，状态包含羊的位置、开启的传送门、阶段、录制历史或未消费的回放指令。回放耗尽或黑羊消失后，不再将旧指令计入搜索状态。若按深度搜索到某一步存在未覆盖的环境循环，只有在同一深度找到已知解时才返回最短解。页面区分搜索穷尽、到达资源上限和环境变化未能结算三种结果。

## 演示地图与人工验收

两张示例都是自制演示地图。

| 演示地图     | 最短解            | 回放观察点                                         |
| ------------ | ----------------- | -------------------------------------------------- |
| 黑羊撑桥     | `→ → →` / `D D D` | 第一步金羊踩机关并生成黑羊，第二步黑羊接替踩住机关 |
| 梯子与传送门 | `↑ → →` / `W D D` | 上梯开门，第二步传送并关门，第三步抵达 G           |

- 启动本地项目后，从首页打开工具，再直接访问并刷新 `/golden-scapegoat`。切换简体中文和 English，确认标题、控件、提示和回放更新。
- 用空白地图放置 S、G、平台和一段梯子，导出再导入并检查坐标和分组。尝试在活动平台格放置机关，确认布局未被修改。
- 运行两张演示图，逐步检查两羊位置和机关状态。跳到最后一帧后复制箭头和 WASD 到外部文本框。缩窄窗口后查看地图滚动和回放定位。
- 将「梯子与传送门」的搜索状态数上限设为 1，确认提示达到上限。检查一个无路可走的地图显示无解。在较大地图搜索期间点击取消或切换地图，确认旧结果不会覆盖当前地图。
