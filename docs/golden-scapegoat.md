# 黄金替罪羊求解器

从首页打开「黄金替罪羊求解器」，也可以直接访问 `/golden-scapegoat`。顶部操作在编辑和回放阶段均可使用。选择「载入演示地图」打开示例，选择「新建地图」清空地图与回放。使用「导出」下载 JSON，用「导入」继续编辑。

## 绘图与回放

1. 在「编辑地图」的顶部工具栏选择画笔，点击格子放置。使用键盘时，可在地图内用方向键选格，再按 Enter 放置。点击擦除会清空该格的全部元素，并移除经过该格或以该格为端点的梯段。擦除多格平台的一格会保留其余格子。
2. 选择活动平台组或传送门组后，在右侧属性面板的「绘制内容」中选择要放置的元素。活动平台分为黄、蓝两组，传送门分为红、绿两组。空组会自动创建。画平台时通过「激活条件」设置按下或松开机关时存在，点击同组已有平台可修改其极性。传送门组的标题显示已放端点数，并可设置初始开启状态。新建时默认开启。导入含更多组的地图后，可在工具栏的「其他导入分组」中选择它们。
3. 面板底部的「待完成」显示缺项数量，默认展开。点击可操作的缺项会选择相应画笔或聚焦记录步数 K。列表可折叠，补齐后会隐藏。空白地图的 K 留空，填入正安全整数并补齐地图后可以求解。梯子用同列两个落脚格定义，图形从上端落脚格的下一行开始，画到下端落脚格。
4. 选择「开始求解」。Worker 使用 100,000 个状态和 5 秒的内部限制。达到限制时会提示资源不足。取消、编辑地图、换图和离开页面都会终止进行中的任务。
5. 找到解后，页面进入「解法回放」，停在初始环境结算后的第 0 步。右侧面板顶部显示最短解步数和两个复制按钮。方向箭头用空格分隔，WASD 连续输出，例如 `DDDDAAAAAW`。剪贴板不可用时，可以手动选取并复制完整序列。

操作节点左上角显示步号，金色方向三角在上半区居中。第 K+1 至 2K 步在下半区用较小的蓝色方向三角表示黑羊从记录中消费的指令。黑羊消费了指令但未主动移动时，三角显示为灰色。黑羊尚未开始回放、已经消失或完成回放时，下半区留空。超过 60 步的序列可翻页查看，当前选中项会滚入面板内的序列区域。

「下一步」播放两羊的同步主动动作，再显示机关变化、坠落、传送、生成和消失。黑羊结束回放后仍可能受环境影响。点击操作节点、上一步、起始帧或最后一帧会直接显示对应快照。快速导航会取消进行中的动画。系统启用减少动态效果、棋盘视窗发生变化或事件无法在当前视窗可靠呈现时，也会直接显示快照。

当前步数和四个图标按钮位于面板底部。有额外事件时可在导航上方展开「本步事件」。长事件列表在详情区内滚动。两羊位置可从棋盘图标和对应格子的提示查看。

同组平台和机关使用相同颜色。平台用横条表示，开启的传送门有实线门框，消失的平台和关闭的传送门有虚线轮廓。起点用路标表示，终点用旗帜表示，金羊为金色羊头，黑羊为浅色描边的深色羊头。格子的提示和可访问名称提供坐标、组名与状态。

编辑模式的地图标题栏可以改变列数、行数和格子大小。地图底部的箭头每次平移半个视窗，定位按钮回到关卡内容，保留行列数和缩放。坐标为整数，X 向右、Y 向下，范围为 ±1,000,000。视窗范围只影响显示。桌面可以拖动地图与属性面板的分隔条，窄屏按地图、属性面板的顺序排列。

回放采用相同的分栏和窄屏布局。地图按关卡实际范围缩放，超过 32 行或列时跟随金羊，并在范围允许时同时显示黑羊。切换页签会保留各自的视窗和回放步骤。

## JSON 格式

版本 2 的根对象包含 `version`、`k`、`start`、`goal`、`floors`、`platformGroups`、`ladders` 和 `portalPairs`。坐标写为 `{"x": 0, "y": 0}`。

| 字段             | 内容                                                                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `version` / `k`  | 固定为 2 的文件版本 / 正安全整数 K，草稿中的 K 可以为 `null`                                                                        |
| `start` / `goal` | 坐标，草稿可以为 `null`                                                                                                             |
| `floors`         | 固定平台坐标数组                                                                                                                    |
| `platformGroups` | 每组含 `id`、机关坐标数组 `controllers` 和平台数组 `platforms`。每个平台含 `id`、非空坐标数组 `cells` 和布尔值 `enabledWhenPressed` |
| `ladders`        | 每段含同列的 `top` / `bottom` 坐标，`top.y < bottom.y`                                                                              |
| `portalPairs`    | 每对含 `id`、端点坐标数组 `ends`、机关坐标数组 `controllers` 和布尔值 `initiallyOpen`                                               |

`enabledWhenPressed: true` 表示平台在按下机关时存在，`false` 表示平台在松开机关时存在。组 ID 在同类组中必须唯一，平台 ID 在所属组中必须唯一。JSON 文件大小上限为 1 MiB。导入结构或布局非法时，编辑器保留当前地图，并报告字段路径或格子坐标。

每格最多一个支撑平台和一个传送门端点。活动平台不能与任何机关同格。传送门端点可以与活动平台组或其他传送门组的机关同格，同组传送门端点和自身机关互斥。每个传送门组最多两个端点。

可先放梯子或传送门端点，再补支撑，也可导入和导出这类未完成的草稿。求解前，梯子的两个落脚格和每个传送门端点都需要支撑。固定平台和活动平台都算作支撑配置，活动平台的实时启闭由引擎结算。含实际平台的活动平台组须放置至少一个机关。含端点或机关的传送门组须有两个端点。没有机关的传送门可以求解，初始开启时一次使用后关闭，初始关闭时保持关闭。完全空的组可保留。

导入版本 1 时，K 仍须为正安全整数。互补的 `defaultEnabled` 与 `activatedEnabled` 会迁移为组内单个平台，其极性取 `activatedEnabled`，原组的 ID、机关及全部平台格保留。没有平台格的组迁移为空平台列表。两个值相同的组会收到带组路径的诊断，须在原文件中确认需要的行为。版本 1 中省略 `initiallyOpen` 的传送门按关闭导入，显式配置保持原值。再次导出时采用版本 2。

## 规则与当前假设

金羊左右各移动一格，沿梯子直接移动到对应端点。无效的金羊输入不推进步数或回放。第 K 次有效操作结算后在 S 生成黑羊，并立即结算它带来的环境变化。黑羊从第 K+1 步起尝试回放记录，依次消费指令。回放结束后保持位置，仍参与环境结算。

每步先从旧状态计算并同时提交两羊的主动位移。根据新位置检查终点与碰撞，读取机关并刷新支撑，再处理传送和同步坠落。活动平台组的任一机关格被占用即视为按下，组内每个平台按自己的极性提供支撑，因此同一轮结算可以同时出现一部分平台并移除另一部分。机关占用和平台启闭会记录为回放事件。一次操作引起的连锁变化会在下一步前全部结算。

踏上有固定平台的机关格才会按下机关。羊进入同时放有传送门端点和其他组机关的格子时，机关先结算，随后才处理传送。双端同步传送允许交换位置，门随后关闭。传送门在机关格从无人占用变为有人占用时开启，并保留开启状态至传送。当一只羊持续按住开关导致另一只羊往返传送时，往返的羊会消失。

以下边缘情形采用了 MVP 假设，表中的摆法仅用于验证时序，均为合成场景。

| 验证摆法                                                         | MVP 行为                                           | 实机待核对的行为                                 |
| ---------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------ |
| 金羊走入空列，列中间有无支撑的传送门机关，下一格有落脚平台       | 经过机关时不激活，只有站在有固定平台的机关格才触发 | 经过机关也可能开门                               |
| 开启的门位于即将消失的活动平台上，金羊和令平台消失的黑羊同时到位 | 优先从已经开启的端点传送，再在落点判断重力         | 可能先坠离门格                                   |
| 黑羊站在 G，金羊横移进入同一格                                   | 同一位置快照先判定金羊到达 G                       | 游戏可能先判碰撞                                 |
| 两个有固定平台的梯子端点之间放置 G，或关闭某个端点的活动平台     | 梯子主动位移只检查端点，端点失去支撑后会下落       | 可能检查梯子途中位置，或者允许在无支撑的端点挂梯 |
| S 未配置平台，G 位于 S 正下方                                    | 初始化即结算坠落，经过 G 得到零步解                | 实机编辑规则可能要求 S 或 G 自带支撑             |

每次同步下落跳过无事件的空段，在下一处地图元素、潜在碰撞位置或最下方已录入格子的下一行重新结算。坠出后金羊失败，黑羊消失；黑羊消失后仍可继续求解。

搜索和回放共用同一状态转移。BFS 以有效操作计成本，状态包含羊的位置、开启的传送门、阶段、录制历史或未消费的回放指令。回放耗尽或黑羊消失后，不再将旧指令计入搜索状态。若按深度搜索到某一步存在未覆盖的环境循环，只有在同一深度找到已知解时才返回最短解。页面区分搜索穷尽、到达资源上限和环境变化未能结算三种结果。

## 演示地图与人工验收

默认演示地图来自 [sample5.json](../src/tools/golden-scapegoat/sample5.json)。地图包含一组活动平台、一段梯子和一对初始开启的传送门。K 为 4，起点为 (0, 0)，终点为 (5, 1)。最短解为 `→ → → → ← ← ← ← ← ↑`，对应 `DDDDAAAAAW`。

- 在 1440px、1024px 和 390px 宽度下打开工具，逐一选择工具栏画笔。检查四色在工具栏、棋盘、机关和面板中一致。用鼠标和键盘调整桌面分隔条，检查窄屏下工具栏和棋盘可分别滚动，页面宽度保持稳定。切换简体中文和 English。
- 用空白地图放置 S、G、同组的两种极性平台、一段梯子和一个传送门端点。检查等宽切换按钮、极性保留和标题旁的端点计数。用鼠标与键盘检查「待完成」的折叠、列表滚动和画笔定位，确认 K 和求解按钮在切换工具、展开列表和补齐条件时保持在面板底部。填写 K 后再清空，导出再导入并确认 K 仍为空。
- 将传送门端点与另一个组的机关放在同一固定平台上，检查可以放置。尝试叠放自身机关，确认出现错误。将格子缩到 32px，用起点、终点和羊头与门框、机关同格的画面检查图标、边框、底部状态和提示。
- 调整行、列和格子大小，使用棋盘箭头平移，再点击定位回到关卡。求解演示地图。在桌面检查回放地图和面板的上下边缘，拖动分隔条并确认节点等高、导航按钮等宽铺满整行。在窄屏确认地图在前，较长序列在面板内滚动。
- 在桌面和窄屏检查操作节点的金色和蓝色实心三角、选中描边及横贯卡片的分隔线。检查不同方向、灰色无效指令和无黑羊指令时的空白下半区，并确认小三角与分隔线之间留有间距。交替选择有事件和无事件的步骤并展开、收起详情，确认当前步数和四个按钮始终位于面板底部。
- 用鼠标和键盘点击节点跳帧、逐步前进并展开事件。用演示地图第 4 步检查传送和黑羊生成，第 5 步检查双羊同步位移，第 10 步检查上梯。动画期间快速切换到首帧或末帧，再启用系统减少动态效果并重复导航，确认棋盘直接显示所选帧。切换页签后检查编辑视窗和回放步骤。复制两个格式，确认箭头之间有空格、WASD 无空格。
- 检查无解和达到资源限制时的不同反馈。在较大地图的搜索期间点击取消或切换地图，确认旧结果不会覆盖当前地图。
